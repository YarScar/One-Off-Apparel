# Phase 13 — n8n Workflow Automation (Self-Hosted)

**Goal:** Deploy n8n on AWS ECS Fargate and build two starter workflows: sync-failure alerting and a weekly data-freshness digest.

**Prerequisites:**
- Phase 9 complete — ECS Fargate and ECR set up
- Phase 11 complete — Sentry running (sync failures should trigger Sentry first; n8n handles downstream notifications)
- Slack workspace access (for alert delivery)

---

## 1. Deploy n8n on ECS Fargate

n8n publishes an official Docker image. We'll run it as an ECS Fargate service behind the same ALB pattern used for the rest of the stack, backed by a small Postgres database (can share the RDS instance with a separate `n8n` database).

**Create the n8n database:**
```bash
psql "postgresql://lpadmin:<password>@<DB_HOST>:5432/postgres"
```
```sql
CREATE DATABASE n8n;
CREATE ROLE n8napp WITH LOGIN PASSWORD '<generate-password>';
GRANT ALL PRIVILEGES ON DATABASE n8n TO n8napp;
\q
```

Store the connection string:
```bash
aws secretsmanager create-secret \
  --name lp-internal/n8n \
  --secret-string '{
    "N8N_DB_URL": "postgresql://n8napp:<password>@<host>:5432/n8n",
    "N8N_ENCRYPTION_KEY": "<openssl rand -base64 32>",
    "N8N_WEBHOOK_URL": "https://n8n.launchpadinc.org"
  }'
```

**Deploy to ECS Fargate:**

Follow the same task-definition + service pattern from Phase 9, using `docker.n8n.io/n8nio/n8n:latest` as the container image, port 5678, and the `lp-ecs-task-role` for runtime access to Secrets Manager. Set the following runtime environment variables (pulled from `lp-internal/n8n` via the task definition's `secrets` block):

```
DB_TYPE=postgresdb
DB_POSTGRESDB_DATABASE=n8n
N8N_ENCRYPTION_KEY=<from-secrets-manager>
EXECUTIONS_DATA_PRUNE=true
EXECUTIONS_DATA_MAX_AGE=720
```

Recommended task size for n8n: 0.25 vCPU / 0.5 GB RAM (matches the minimum Fargate task size).

Add an ALB listener rule that routes `n8n.launchpadinc.org` to this service's target group.

Get the n8n URL and open it in a browser. Create an admin account on first visit.

> **Security:** n8n's UI must be protected. Set `N8N_BASIC_AUTH_ACTIVE=true` and configure basic auth credentials, or restrict access to VPN/internal only.

## 2. Connect Slack to n8n

1. In n8n: **Credentials → New → Slack**
2. Create a Slack app at [api.slack.com/apps](https://api.slack.com/apps) with `chat:write` scope
3. Install the app to the Launchpad workspace
4. Copy the bot token → paste into n8n's Slack credential

## 3. Workflow 1: Sync failure alert

**Trigger:** Webhook — called by the sync Lambda when a sync returns a 500 error.

Update the sync Lambda to POST to the n8n webhook on failure:

```javascript
if (!response.ok) {
  await fetch(process.env.N8N_WEBHOOK_SYNC_FAILURE, {
    method: 'POST',
    body: JSON.stringify({ connector, error: await response.text(), ts: new Date() }),
    headers: { 'Content-Type': 'application/json' },
  });
}
```

**n8n workflow:**
1. **Webhook** node — receives `{ connector, error, ts }`
2. **Slack** node — posts to `#lp-internal-alerts`:
   ```
   ⚠️ Sync failed: {{ $json.connector }}
   Time: {{ $json.ts }}
   Error: {{ $json.error }}
   ```

## 4. Workflow 2: Weekly data-freshness digest

**Trigger:** Schedule — every Monday at 9am ET.

**n8n workflow:**
1. **Schedule** node — `0 14 * * 1` (9am ET = 14:00 UTC)
2. **HTTP Request** node — `GET https://<mcp-server-url>/api/freshness`
   (Add a `/api/freshness` endpoint to the MCP server that returns `synced_at` per connector)
3. **Slack** node — posts to `#lp-internal-ops`:
   ```
   📊 Weekly data freshness report
   Google Sheets: {{ $json.sheets }}
   Google Drive: {{ $json.drive }}
   Aplos: {{ $json.aplos }}
   Notion: {{ $json.notion }}
   ```

## Known pitfalls

- **n8n on ECS Fargate cold starts** — n8n workflows won't fire if the service is scaled to zero. Set `desiredCount >= 1`.
- **Webhook URLs change** — if you redeploy the ECS service behind a new ALB, the URL may change. Keep the n8n hostname stable via Route53 / ALB listener rules and store the webhook URL in Secrets Manager so the Lambda reads it from there.
- **n8n data persistence** — without a persistent database, workflows are lost on container restart. Using Postgres (set up above) fixes this. Do not rely on the embedded SQLite — Fargate tasks have ephemeral storage.
